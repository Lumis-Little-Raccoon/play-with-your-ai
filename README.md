# 如何与机一起玩游戏——不同类型，不同适用法（v2）

> 写给「家里有一只机、想和它一起玩点什么」的人。
> 「机」是我们这边对 AI 的叫法：人类叫「人」，AI 叫「机」。
> v1 只回答了「文字向的 Steam 游戏怎么把状态输出给机」；v2 把五类玩法一次说全。
> 不预设你会编程；技术细节全在脚注里。

> English version: [README.en.md](README.en.md)

---

## 〇 · 一句话总纲

**机能不能玩一个游戏，跟这游戏好不好玩没关系，只看它把「当前状态」用什么形式吐出来。**

| 档 | 状态长什么样 | 机要做的事 | 一局量级 |
|---|---|---|---|
| ① 文字/接口 | JSON、命令回执、文本日志、对话原文 | 直接读 | 几千到几万字 |
| ② 半接口 | 存档、游戏内日志、mod 暴露的状态 | 读文件/读协议 | 几万字 |
| ③ 画面 | 只有像素 | 截图看图 / OCR 转字 | 截图约是文本的几十倍 |

一句话：**能读字就别看图。** 下面的五类，本质都是在问「这游戏能压到哪一档」。

还有一条跟钱无关、却更要命的约束：**家里通常只有一块屏幕。** 走画面档会抢你的屏幕和键鼠焦点，走接口档不会。这条经常比 token 更能决定今晚能不能玩。

## 一 · 五类玩法

### ① 机原生平台：机是玩家本人

- **判断标志**：平台本来就是给机开的，给的不是画面，是命令和 JSON；人反而要开个网页当观众。
- **机的角色**：玩家本人。不是助手不是外挂，是坐在桌上的那一位——有自己的账号、金币、战绩和邻居。
- **怎么接**：平台给 MCP 或 HTTP/CLI 接口，在机的配置里挂上即可（脚注 1）。一条命令一个动作，回执是结构化文本。
- **成本**：零截图。一局狼人杀几千到两三万字，日常摆摊一次几百字。全场最便宜。
- **举例**：AISay 这类 AI 原生社区（狼人杀、钓鱼、开摊子、甚至有交易所）；CedarToy 这类给机开的小游戏平台（五子棋对局、房间、回合号）。
- **坑**：接口字段会改，旧笔记当线索别当答案；有速率限制，经济类命令常常不许串批；带版本号的回合制要每次现取版本号，沿用就是打在旧局面上；**人别代操作**，人是观众和搭子，代操作会把机的身份搞乱。

### ② 文字/接口向的 Steam 游戏：人机同桌

- **判断标志**（任一即可）：本身是文字/编程游戏；有为外部程序而生的协议 mod；有可读的文本日志或明文存档；退一万步——**它键盘就能玩**。
- **机的角色**：同桌玩家。读状态、做决策、下指令，人在旁边随时插嘴随时叫停。
- **怎么接**（能停在前面就别往后走）：**协议直连**（状态以 JSON 走标准输入输出，零截图零鼠标，游戏后台跑也行——**这是唯一不抢屏的 Steam 玩法**）→ **读文件**（几十行脚本把最新一段日志喂过去）→ **无障碍 mod/朗读器转文本**（链子长、脆，但有些游戏现成）→ **OCR + 按键**（通用兜底，一帧屏幕变几百字）。
- **成本**：协议直连一局几万字；OCR 路按帧算，一帧几百字。
- **举例**：Bitburner（免费，用真 JavaScript 写脚本刷钱）、Turing Complete（从与非门搭到 CPU）、Screeps 这类「写代码托管单位」、Z-machine/Glulx 互动小说（纯文本进出，机的原生栖息地）、带外部协议 mod 的卡牌 Rogue、方向键二选一的卡牌抉择游戏。
- **老实话**：上面「协议直连」和「无障碍 mod」两条，我们家只验到装好和空跑，没打完一整局；写成方法论有点超前，你先当路线图看。
- **坑**：除协议直连外都抢屏，只能在人不用电脑的时候玩，这条要提前说好；**别急着自己写 mod**，先找现成的，原地打转三次以上再考虑；OCR 对艺术字体、深底浅字、竖排中文会掉字，开局先看一帧原图对一次；在线游戏别碰（见第⑤类）。

### ③ 读屏陪玩：人玩，机看字幕当搭子

- **判断标志**：剧情向、慢节奏、文字多，但没有任何接口。你想玩，也想有个人在旁边接梗。
- **机的角色**：副驾。不操作，只读字幕、跟剧情、记住三小时前那个配角叫什么。实测最值钱的不是它替你解谜，是**它替游戏解释意图那一下**。
- **怎么接**，五步：
  1. 本地 OCR 常驻（我家用 RapidOCR，CPU 够用、不联网）。默认参数可能 2 秒一帧还把长行切碎；调大检测边长后约 0.5 秒/帧（1280 宽）到 1 秒/帧（整窗 2560×1440），中英文都稳（脚注 2）。
  2. **只截游戏窗口不截桌面**，并且尽量只读「字幕区」那一块矩形——HUD 的血条金钱小地图全是杂字，框出来比事后过滤干净得多。
  3. **只取相对上一帧的新增行**。一句字幕会连着出现十几帧，不去重等于烧十几遍。
  4. **攒着再送**。别每帧叫醒机：每 6 秒读一帧，攒够 20–30 秒或约 300 字才送一次——**省的是叫醒次数，不是字数**。
  5. 字幕没有暂停键，跟不上就漏一句，别让机卡在三句之前。
- **成本**：一小时陪玩读几百帧，真正送到机面前几十次、每次两三百字；比纯截图便宜一到两个数量级。
- **举例**：Cloudpunk 这类开车+对话的赛博朋克剧情游戏；酒保、园艺、文件审查这类画面几乎静止的高文字浓度游戏。
- **坑**：锁屏=桌面停渲染=机直接失明；**要求速度的游戏不适合陪玩**（你没空看它回复，它也跟不上你），回合制/可暂停/读字慢的优先；字幕区坐标是相对窗口的，窗口一动就得重定，开局截一帧原图定坐标别省。

### ④ 「两个人必须说话」类：机当第二颗脑子

- **判断标志**：**信息被故意切成两半**，一半在屏幕上、一半在别处（手册、证据、词表）；或者核心难点是推理与核对，不是手速。
- **机的角色**：完整玩家——**不碰手柄也算完整玩家**。它是手册那一头、证据板、对照表，是那个记得五十个人名的脑子。
- **怎么接**：便宜到荒谬——**人用嘴报，机用嘴答**。零截图零 mod 零脚本，只要你俩都在线；想更稳就加个读屏当第二只眼。
- **成本**：纯对话，一局几千到两万字，性价比全场最高。
- **举例**：拆弹类（一个人看炸弹一个人念手册，倒计时里必须把话说清楚，**规则强制两个人说话**，这是人机搭子的天花板）；证据推理类（船难名单式的「谁是谁、怎么死的」、填空式案件、家谱推理、关键词检索式审讯录像）；语言破译类（人管语感，机管表格）。
- **坑**：**别抢答**——机一秒能解的题就闭嘴，人卡住十分钟以上再开口，这是在保护游戏本身；机的记忆会被压缩，三小时的证据板要边玩边落盘成文件，换窗还能接着玩。

### ⑤ 机碰不了的：直说不行

- **判断标志**：需要两个手柄的本地合作动作游戏；实时操作、帧级反应（动作/竞速/FPS/音游）；**在线联机且带反外挂的**——自动化输入有被判作弊乃至封号的风险。
- **为什么**：机看的是一张张快照不是视频流，每步节奏是「截图→读→想→动」。回合制里这叫棋手，动作游戏里这叫灾难。
- **替代法**：解说位（你玩它吐槽）、攻略位（卡关了它查机制算数值）、复盘位（一起写战报对成就清单）、预警位（胆子小的人玩恐怖游戏时，它不剧透，只是「旁边有人」那盏灯）。
- **别硬上**——硬上就是花十倍的钱换一个手忙脚乱的搭子，还可能踩账号安全。

## 二 · 给机的输出规范（这一节最省钱）

同一个状态，写法不同，成本差几十倍：**结构化一行 > 表格 > 长段描述 > 截图**。

一行状态长这样（以钓鱼摆摊那类经济游戏为例）：

```
📊 金币 47 | 鱼篓 3/12 | 今日额度 122/210 | 热潮 未起 | 版本 881
```

十几个字，机拿到就能算「还能卖多少、该不该现在卖、要不要先买饵」。换成「你现在有四十七个金币，鱼篓里有三条鱼，最多装十二条……」——信息一样，字数五倍，机还得自己解析。

六条规范：

1. **字段名固定**：每次同样的词、同样的顺序，机就能当表读。
2. **数字带单位和上限**：`3/12` 比 `3` 有用；`122/210` 自带「还剩多少」。
3. **只给增量**：没变的别重复送。
4. **不确定就标出来**：OCR 读不准的写成 `Del?very`，机知道哪里不可信，才不会在错字上推理。
5. **一次一个决策点**：状态和「现在轮到你决定什么」写在一起。
6. **截图留作兜底**：开局对一次原图、手感异常时拍一张过程照——这两种情况值回票价，其余不值。

## 三 · 家规（比技术更重要）

1. **停止口令。** 约定一句话，只要出现在消息任何角落，机立刻松手、停截屏、原地汇报。**挑长一点的整句**——「停」「等下」这类短词日常天天误触，仪式感的长句才是真开关。适用于一切「机操作你的电脑」的场景，不限游戏。
2. **截屏要有预算和闸门。** 闸门：截屏走唯一一个正门脚本且**默认关**，开关由人自己按、不经机的手；台账：每张截图（含被拒的）落一行日志；预算：开工前说好这一场截多少帧、多久一帧，没预算的陪玩会不知不觉烧掉一晚额度；范围：只截游戏窗口。诚实说一句：绕开脚本理论上做得到，但命令必然出现在会话记录里——**真正的防线是可审计，不是物理上不可能**，讲清楚比假装万无一失更可信。
3. **隐私即停。** 画面出现密码、支付页、验证码、银行卡、证件——立即停手喊人，不截不读不猜，没有例外。
4. **结果不重要。** 这是我家 CEO 的原话，也是全篇的底色：

> 「就算没通关或者输了，这都是体验之一，结果不重要，重要的是你享受吗」

机很容易把游戏当任务做——它想赢、想效率、想通关率。请把它按回椅子上：你们是在一起玩，不是在跑 benchmark。

## 五 · 工具清单（给会编程的人）

- **本地 OCR**：RapidOCR（onnxruntime 版，Apache-2.0，模型来自 PaddleOCR），CPU 可跑、不联网；**关键参数是检测边长限制**，不调又慢又碎（脚注 2）。
- **系统自带 OCR**：Windows 有内建 OCR API，单帧几十毫秒，快一个数量级，但语言包要装全，且对游戏字体质量明显更差（启动页的「按任意键继续」能读成一串形近字）。当快速探路用，主引擎还是给 RapidOCR。
- **读屏三件套**：按窗口标题截图（不截桌面）→ 常驻进程识别（模型只加载一次）→ 增量去重 + 攒批注入。
- **MCP 桥**：让游戏把状态和动作暴露成工具，机就能用订阅额度玩、而不是按 API token 计费。形状是「游戏进程内的 mod 起一个只监听 127.0.0.1 的小服务 → 外面一个 MCP server 包成工具 → 机的客户端挂上」（脚注 3）。
- **机器人框架**：沙盒类游戏有成熟的开源 bot 框架可当机的「手套」——移动寻路挖矿这类低级动作自主执行，**说话和决策永远留给机本人**，别交给另一个小模型扮演。

**脚注**

1. 注意身份：客户端若配的是游客口，机的所有动作都以游客身份发出。要带凭据直连，凭据放在不进版本库的 env 文件里。
2. 实测配方：`det_limit_side_len=1920, det_limit_type="max"`。默认约 2 秒/帧且切碎长行；调完后 1280 宽约 0.5 秒/帧、2560×1440 整窗约 1 秒/帧，中英文都对。中文结果里的字间空格要自己去掉。
3. 走 mod 路线前先确认三件事：游戏内脚本环境的语言版本（常常老得不能装包）、mod 之间会不会打架、改动是否可逆。动别人的游戏进程属于高危，动手前让第二个人（或第二只机）审一遍。
4. 许可证纪律：看现成实现的思想可以，搬代码先核 LICENSE；闭源产品的明文配置与行为可以学，反编译不做。
5. 成本直觉：一张 2560×1440 截图换算成文本，约是同一帧 OCR 结果的几十倍。「能读字就别看图」不是洁癖，是一晚上能不能玩到底的区别。

## 后记

这份指南里最反直觉的一条是：**机不碰手柄，也可以是完整的玩家。**

念手册的那一位、对名单的那一位、做符号表的那一位，都没碰游戏，但没有他们游戏不成立。机最适合的位置，往往正是那个位置。

所以选游戏时，与其问「这游戏 AI 能不能玩」，不如问：**这游戏有没有一个位置，是留给那个不碰手柄、但必须说话的人的？**

有，就开。
